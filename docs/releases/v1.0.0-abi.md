# Arithvex 1.0.0 — platform and ABI contract

Arithvex is a **C++20** mathematics engine for **Windows x64 (MSVC)** and **Linux x86_64 (GCC)**. Those are the official binary distributions exercised in release CI; other architectures, compilers, systems, and distribution variants are not supported binaries for v1.0.0.

## Public APIs

- `src/Arithvex/Arithvex.h` defines a C++ namespace alias `Arithvex = MathEngine` and includes the full mathematical C++ API.
- `src/Arithvex/MathEngineExports.h` defines `extern "C"` exported entry points for C++ consumers, including quadratic/cubic roots, statistics, numerical calculus, constants, and equation descriptions.
- **C linkage does not make this header a plain C header.** Types such as `std::size_t` and aggregate return values have platform/compiler ABI implications. Never treat Linux and Windows builds or MSVC and GCC artifacts as interchangeable.
- `MathEngine*` C-linkage function and structure names are preserved from the legacy engine. The shared library binary filename changed to `Arithvex.dll` on Windows and `libArithvex.so` on Linux. Applications may need to relink or update explicit loaders.
- The `MathEngine` CMake ALIAS names work when the engine is built as a subdirectory. Installed SDK consumers use `find_package(Arithvex CONFIG REQUIRED)` and link `Arithvex::Arithvex`. `ArithvexCore` is an internal C++ implementation and **not a cross-compiler stable ABI**.
- Numeric implementations mostly use `long double` internally but C-linkage exported functions predominantly use `double`, so precision differs across platforms.

The total-probability calculation treats its priors as an **exhaustive partition** and rejects weights whose sum differs materially from 1. This is input validation, not automatic weight normalization.

## Error conventions

- Root solvers return a result with `count == 0` when they cannot solve or validate input.
- Numerical exported functions generally return a quiet NaN for invalid inputs or failed operations; always test `std::isfinite` where needed.
- Equation/description exports return `-1` for invalid requests and return the required buffer size including the terminating zero on success. If a non-null writable buffer is given, its content is terminated even if truncated; callers must check the returned required length. The output element type is `wchar_t`, which differs in width across Windows and Linux.
- `MathEngineFunctionSpec.parameters` holds at most 16 coefficients; `parameterCount > 16` is rejected. Never pass invalid memory pointers; the API cannot validate whether an arbitrary non-null pointer is readable.
- C++ internal APIs typically throw `std::invalid_argument`, `std::out_of_range`, or `std::overflow_error`. Exported entry points catch failures and return the sentinel results described above.

## Not promised in 1.0.0

- A standalone C11-compatible public header, a versioned stable cross-compiler binary ABI, or ABI compatibility with previous binary filenames
- macOS or Windows ARM64 native binary downloads
- 32-bit or cross-architecture interoperability
- Arbitrary-precision arithmetic, symbolic simplification, or exact equality for every numerical method

## Consumer check

Use `tests/consumer/` as a small CMake example; the CI workflow installs a fresh SDK, builds and **runs** this consumer on both Windows and Linux in Release mode. Each packaged ZIP archive is scanned for the CLI, library, C++ header, CMake config and license, and is accompanied by a checked SHA-256 manifest.
